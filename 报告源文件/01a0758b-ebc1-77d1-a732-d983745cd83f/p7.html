（一）核心创新点

本作品的创新并非单点突破，而是「算法三项 + 端侧三项」的组合：算法侧针对变化检测的三个固有难点提出专门结构，端侧三项则打通从浮点权重到可交付系统的三个工程断点。

序号创新点价值
①RTRF 互易时相响应融合
同时构造差异、能量与一致性三种响应，再做通道路由与空间路由		把光照阴影、季节差异等伪变化与真实地物变化区分开，从源头降低误报
②MSRB 多尺度细化桥
尺度上下文聚合 + 跨尺度细节融合		兼顾从单栋建筑到大片区开发的尺度跨度，缓解小目标漏检
③SAM 注意力解码
解码阶段对通道与空间位置重新加权		守住道路、田埂、围栏等细长边界，提升面积统计的可用性
④面向边缘芯片的结构前置适配
以目标架构的算子集与数值格式反向约束网络结构与导出方式		避免「先在服务器上做精、再想办法塞进板子」的返工循环
⑤真实数据校准的量化策略
60 组真实样本校准，配合浮点自检交叉验证		在压缩约 68% 体积的同时保住精度，形成可复现的量化路径
⑥端侧「可视化—可量化—可解释」闭环
六视图联动、四色误差图、精度指标与视觉大模型语义解释集成于同一界面		把检测结果从单个二值掩膜，升级为一线人员可直接使用与判断的信息
三项算法创新 + 三项端侧创新，共同构成一套「为边缘硬件而设计」的变化检测方案：算法在结构上就为量化留出余量，工程流程又用真实数据把量化误差压回可接受范围，二者互为前提。

（二）应用场景与推广

本作品面向的是「需要到现场、且现场没有网」的一类遥感解译需求。端侧推理把原本依赖云端的能力前移到作业现场，在三个方向上直接对应真实业务：

应用场景核心需求端侧方案提供的价值
灾害评估尽快掌握损毁范围与面积现场直接给出变化区域与面积统计，不必等待影像回传与云端排队，为救援决策争取时间
城市更新与违建监管定期比对新增建筑与地表变化自动圈出变化图斑，把「人工逐幅排查」变为「按图斑核查」，显著减少工作量
国土动态监测需要可核验的图斑与面积数据四色误差图与逐像素指标提供可复核依据，便于形成规范的监测记录

无人机

作业区无网亦可出结果

巡检设备就地检测
结果当场可查
调度平台
变化图斑与面积数据
回传至指挥与监管系统

可移植性与演进方向

整条链路与具体模型解耦：更换网络定义与权重，重新执行导出与量化即可平移到其他边缘平台，具备良好的可移植性。在此基础上，后续可沿两个方向延伸——一是把单幅检测扩展为批量评估与长期序列比对，形成区域变化的趋势记录；二是把变化图斑接入风险预警看板，由「发现变化」进一步走到「评估风险、提示处置」，使系统从检测工具演进为服务于国土监管与应急调度的端侧感知节点。

一句话总结：用自研轻量化算法把变化检测能力压缩进 3.2 MB，再把它交给一块 4 GB 的国产边缘板卡——让遥感解译第一次可以发生在数据产生的地方。

（一）关键参数速查

环节参数
训练骨干 MobileNetV2（权重共享）；总参数量 2,477,892；输入 x1 / x2 各 [1,3,256,256]，输出 change_map；浮点权重 10.2 MB
导出PyTorch → ONNX，opset 11；导出前校验输出形状为 (1,1,256,256)
量化hb_mapper 1.24.3；march = bayes-e；int8；校准 60 组真实样本，每组 786,432 字节
板端模型 repbnet_cd.bin（3,279,032 字节）；运行时 hbm_runtime；判定阈值 0.5
指标LEVIR-CD 全量 2048 对：P 0.8782 / R 0.8517 / F1 0.8648 / IoU 0.7617；UAV：F1 0.7752 / IoU 0.6329
界面板载 1024×600 IPS 触摸屏；本地 Web 服务，浏览器访问；模型常驻内存只加载一次

（二）端侧文件清单与复现步骤

文件作用
repbnet_cd.bin板端可执行的 int8 定点模型，全部推理的基础
infer.py推理封装：预处理、模型加载、概率图与统计量计算
webapp.py端侧工作站主程序，提供界面与各功能接口
explain.py调用视觉大模型，生成变化的中文语义解释
batch_eval.py批量评估脚本，逐对推理并计算整体精度指标
static / templates前端样式、交互脚本与页面模板
demo演示用影像对与真值（含 A / B / label 子目录）
